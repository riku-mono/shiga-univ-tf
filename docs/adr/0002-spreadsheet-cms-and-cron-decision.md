# ADR-0002: GoogleスプレッドシートCMS連携方式と定時実行バッチ（Cron）の採否

* **ステータス**: 承認済み
* **決定日**: 2026-11-23
* **対象**: データ同期方式・GitHub Actions 定時実行（`app.js`, `data.js`, `.github/workflows/`）

---

## コンテキスト（背景と課題）

本サイトでは、以下の3種類のコンテンツを Google スプレッドシートで管理し、エンジニア以外の部員・マネージャーでも更新できる CMS として運用する前提となっている。

1. **お知らせ**（トップページ `index.html`）
2. **部員紹介**（`members.html`）
3. **滋賀大記録（大学記録）**（`records.html`）

GitHub Pages へのデプロイメントを想定するにあたり、以下の2点について設計判断・整理が必要となった。

1. **スプレッドシートの更新反映や学年更新のために、GitHub Actions 等による定時実行（Cron）は必要か？**
2. **リポジトリ内に残存している旧ワークフロー（`.github/workflows/update-instagram.yml` / `update_instagram.py`）をどう扱うべきか？**

---

## 決定事項

1. **現フェーズでは「クライアントサイド公開CSV直接同期」を継続し、スプレッドシート反映用の定時実行バッチは採用しない**
   * `app.js` の `syncFromGoogleSheets()` は、閲覧者のブラウザがページを開いた際に Google スプレッドシートの「ウェブに公開（CSV）」URL を直接 `fetch(..., { cache: "no-store" })` で取得し、DOM を動的描画している。
   * また、部員紹介の「1〜4回生・院生」および卒業生・修了生の非表示判定も、`getCurrentAcademicYear()` によりブラウザ側の現在日付（4月〜翌3月を1年度）から毎回自動算出している。
   * したがって、スプレッドシートの編集内容や年度切り替えを反映させるためだけの定期ビルド／定時コミットは不要とする。

2. **形骸化していた Instagram 自動更新用ワークフロー・スクリプトを削除する**
   * `.github/workflows/update-instagram.yml` は毎日 JST 7:00 と 21:00 に `update_instagram.py` を実行して `data.js` 内の `instagramPosts`（`hikone` / `otsu`）を書き換える仕様だった。
   * しかし、過去の仕様刷新（コミット `c527e64` および `08db716`）により `data.js` から `instagramPosts` プロパティ自体が削除されているため、現在は実行されても更新対象が存在せず無意味な定時実行が走るだけの状態になっている。
   * GitHub 上での不要なアクション実行や失敗通知を防ぐため、`.github/workflows/update-instagram.yml` と `update_instagram.py` を削除する（必要になった場合は Git 履歴から参照・復元可能）。

3. **「定時実行／静的ビルド方式」へ移行する場合の判断基準を定義する**
   * 現時点ではシンプルさを優先してブラウザ直接取得とするが、後述の「既知課題」を解消するために将来的に **GitHub Actions（定時実行または Google Apps Script からの `repository_dispatch` トリガー）で静的 JSON/`data.js` を生成・コミットする方式** へ切り替える余地を残す。その場合は新しい ADR を起票して決定する。

## 検討した選択肢とトレードオフ

| 方式 | メリット | デメリット・注意点 |
| :--- | :--- | :--- |
| **A. ブラウザ直接 CSV 取得（現採用・定時実行なし）** | ・GitHub Actions の定時実行や認証管理が不要<br>・シート編集後、Google 側の公開キャッシュ更新（数分程度）だけでサイトへ反映<br>・Git コミット履歴が自動更新で汚れない | ・Google「ウェブに公開」の仕様上、反映に数分のラグがある<br>・シートを「ウェブに公開」にする必要がある<br>・通信エラー時にフォールバック初期データが無いと空白表示になる（`data.js` 側の改善課題）<br>・表示直後に仮HTMLから差し替わるチラつきが起きやすい |
| **B. GitHub Actions 定時実行（例：1日2回 CSV 取得→コミット）** | ・表示が高速でチラつきがない<br>・Google 側の一時障害時も静的サイトとして表示が壊れない | ・次の定時実行時刻まで変更が反映されず、更新確認しづらい<br>・手動実行や GAS Webhook 連携を併用しないと運用者の待ち時間が発生する |
| **C. GAS（Google Apps Script）編集トリガー ＋ GitHub Actions** | ・シート変更時にほぼ即時で静的再ビルドが可能<br>・シートを非公開のまま運用できる | ・GAS スクリプトや GitHub Personal Access Token (PAT) の期限管理・引き継ぎコストが増える |

---

## 現時点で把握している課題（後続フェーズでの対応予定）

本 ADR ではアーキテクチャおよびデプロイ／定時実行の方針を確定したが、非エンジニアによる運用開始までに以下の課題について別途仕様を確定・実装する必要がある。

1. **非エンジニア向けの入稿ミス防止と構造改善**
   * **大学記録シート**：現在は歴代最高（1種目1行）を直接上書きする構成のため、誤削除・旧記録の消失・カテゴリ/性別/記録表記のゆれが起きやすい。「いつ・誰が・どの大会・どの種目・どの記録か」をフォームまたは追記形式で入力して自動集計／入力規則で保護する仕組みの検討が必要。
   * **お知らせシート**：公開/非公開フラグ、並び順・件数制御、リンク先の選択式化（HTML ファイル名手入力の排除）が未対応。
   * **テンプレートの整合**：`spreadsheet_templates/02_部員紹介テンプレート.csv` の列定義が現行本番シート（`役割,種目1,記録1...`）より古い形式のままとなっている。
2. **読み込み中・取得失敗時のフォールバック改善**
   * 過去コミット `08db716` で `data.js` から初期データが削除されたため、CSV 取得失敗時に `records.html` が空表示になる、各ページに「掲載例」等の仮注記が残っている等の表示面課題がある。
3. **お問い合わせフォームの実送信設定**
   * `data.js` の `contactConfig.endpointUrl` が空文字 `""` のため、現在は `mailto:` で端末のメールソフトを起動する動作となっている（直接送信には Formspree または GAS Web アプリ連携が必要）。
